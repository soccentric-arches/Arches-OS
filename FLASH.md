# Flash procedures — Xavier generation

Specific to the Xavier generation (L4T R35.6.4 / JetPack 5.1.6, UEFI boot).
These are **not** the TX legacy-only flow, the Orin R36 flow, or the Thor
unified flow — do not copy them across branches.

All flashing happens from the build output in
`build/tmp/deploy/images/<MACHINE>/`. Put the target in **USB recovery mode**
before USB-dependent flows.

## 1. Internal storage (eMMC) — initrd-flash / doflash.sh

Applies to: `jetson-agx-xavier-devkit`, `jetson-agx-xavier-industrial`,
`jetson-xavier-nx-devkit-emmc`.

JetPack 5 / L4T R35.x supports initrd flashing natively (upstream:
`layers/meta-tegra/docs/initrd-flashing-support.md` — "supported on branches
based off JetPack 5/L4T R35 or later").

1. Build the image for the machine (`make build <board>`).
2. Enter USB recovery mode.
3. From the deploy directory, run the packaged flash tooling:

```sh
cd build/tmp/deploy/images/<MACHINE>
sudo ./initrd-flash
# or, for the legacy tegraflash path generated by the BSP:
tar -xzf *.tegraflash.tar.gz -C /tmp/tegraflash-<MACHINE>
cd /tmp/tegraflash-<MACHINE> && ./doflash.sh
```

Host prerequisites per the upstream doc: `sgdisk`, `udisksctl`, desktop
automount disabled; `bmaptool` is used automatically when available.

## 2. Xavier NX SD media (P3668-0000 dev kit)

Applies to: `jetson-xavier-nx-devkit`.

The flash package tooling generates the SD-card image (the BSP's
`dosdcard.sh`/SD image flow from the extracted `.tegraflash.tar.gz`).
Procedure:

```sh
cd build/tmp/deploy/images/jetson-xavier-nx-devkit
tar -xzf *.tegraflash.tar.gz -C /tmp/tegraflash-jetson-xavier-nx-devkit
cd /tmp/tegraflash-jetson-xavier-nx-devkit
./dosdcard.sh /dev/sdX
```

Write the produced image to the SD card (Etcher or `dd`), then boot the NX
dev kit from SD. First boot on a module that has never run JetPack 5.x
requires a QSPI update first (NVIDIA documents the QSPI image and steps for
this).

## 3. OTA (after first flash)

The SWUpdate infrastructure is carried forward on this branch unchanged
(`make swu <board>`). A/B rootfs slot behavior on R35 (nvbootctrl slots
exist on Xavier) has not been validated with the carried-forward scripts —
see `VERIFY.md`.

## Untested status

No physical target was available in the environment where this branch was
prepared. Every procedure above follows the pinned meta-tegra documentation
and generated artifact names but has not been executed against hardware.
Update `VERIFY.md` when a target is validated.
